# SFT vs 强化学习(RL)：从原理到代码（小白友好版）

一份"看得懂 + 跑得起来"的学习笔记。包含两个例子：

1. **例子一**：`sft_vs_rl_demo.py` —— 纯 Python、零依赖、30 秒跑完，**一眼看懂**两者的差别。
2. **例子二**：`qwen_sft.py` + `qwen_rl_grpo.py` —— 用**真实的 Qwen 模型**分别做 SFT 和 RL。

---

## 0. 一句话总览

| | SFT（监督微调） | RL（强化学习） |
|---|---|---|
| 学习方式 | **照着标准答案模仿**（背书） | **自己答，老师只打分**（试错） |
| 需要的数据 | `(问题, 标准答案)` 成对示范 | 一个**奖励/打分**信号（不需要标准答案）|
| 能力上限 | ≤ 示范数据的质量（学不会示范里没有的） | **可以超越示范**，甚至发现人类没想到的解法 |
| 训练信号 | 每个 token 都有"该输出什么"的密集监督 | 整段输出只有一个稀疏的分数 |
| 难度/成本 | 简单、稳定、便宜 | 复杂、易不稳定、贵 |
| 典型作用 | 教**格式、风格、指令遵循、基础能力** | 对齐**人类偏好、价值观**；提升**推理/做对率** |

> 现实中**不是二选一**，而是**先 SFT 打底，再 RL 拔高**（见第 1 节）。

---

## 1. 先建立全局地图：大模型是怎么练成的

现代对话大模型（ChatGPT、Qwen、DeepSeek…）基本都是三段式：

```
①  预训练 Pretrain         在海量文本上"读万卷书"，学会语言和世界知识
        ↓                  （得到一个会"续写"但不太会"听话"的底座模型）
②  SFT 监督微调            用人工写的 (指令, 优质回答) 教它"好好说话、听懂指令"
        ↓                  （得到一个会聊天、守格式的助手）
③  RL 强化学习             用人类偏好/可验证奖励，把它打磨得更有用、更安全、更会推理
                           （RLHF / RLVR / DPO …）
```

- 没有 ②，底座模型只会胡乱续写，不会回答问题。
- 没有 ③，模型会"听话"但回答质量、安全性、推理深度都有限。
- 为什么不能跳过 ② 直接 ③？因为 RL 从零开始太难（动作空间巨大、奖励太稀疏），
  **SFT 先把模型带到一个"差不多能用"的区域，RL 再在附近精修**，又快又稳。
  （AlphaGo 也是这样：先模仿人类棋谱，再自我对弈强化。）

## 2. 什么是 SFT（Supervised Fine-Tuning，监督微调）

### 2.1 直觉：背标准答案

老师给你一本"题目 + 标准答案"的习题册，你的任务就是**把标准答案背下来、模仿它的写法**。
下次遇到类似的题，你就照着背过的套路写。这就是 SFT，也叫**模仿学习 / 行为克隆**。

### 2.2 机制：本质是"预测下一个词"

模型逐字（token）预测标准答案的下一个字，用**交叉熵损失**让"标准答案里那个正确的字"
概率变大。一句话：

> **SFT 的目标 = 最大化"标准答案"出现的概率**：`minimize  −log P(标准答案 | 问题)`

它只盯着那**一个**标准答案，把它的概率往上推。

### 2.3 优点
- 简单、稳定、便宜，几十~几千条数据就有效果。
- 非常擅长教**格式、风格、指令遵循**，以及把预训练里"沉睡"的知识唤醒出来。

### 2.4 局限（关键！这正是需要 RL 的原因）
1. **天花板 = 示范质量**：示范里没有的更优解，它学不到（例子里会看到）。
2. **只学"正例"，不学"反例"**：只告诉它"要这样答"，从没说"别那样答"，
   所以不擅长**主动避免**坏输出。
3. **Exposure bias（曝光偏差 / 误差累积）**：训练时它看到的前文永远是"标准答案的前缀"，
   但真正生成时它看到的是"自己刚写出来的字"。一旦中途写错，后面会越滚越偏，
   因为它没练过"从自己的错误里爬回来"。
4. 容易**死记硬背**：在没见过的分布上泛化较弱，可能自信地胡说（幻觉）。

## 3. 什么是 RL（强化学习）

### 3.1 直觉：自己答，老师只打分

没有标准答案。你自己写答案，老师**只给一个分数**（好/不好、几分），
你根据分数反复调整，自己摸索出"怎么写能拿高分"。
你甚至可能发明出**比老师还好**的解法。

### 3.2 机制：采样 → 奖励 → 调整概率

```
模型自己生成多个答案  →  打分器(reward)给每个答案打分  →
        提高高分答案的概率、降低低分答案的概率（策略梯度）  →  重复
```

> **RL 的目标 = 最大化"自己生成的答案"的期望奖励**：`maximize  E[ reward(模型生成的答案) ]`

和 SFT 的关键差别：
- SFT 只能**把某个给定答案的概率往上推**；
- RL 能**同时把好答案推上去、把坏答案压下去**，塑造**整个**输出分布；
- RL 训练用的是**模型自己生成**的内容（on-policy），所以天然修复了 exposure bias——
  它就是在练"从自己写的东西里继续往好里走"。

### 3.3 三种常见"奖励"来源（对应三类 RL）
| 名称 | 奖励从哪来 | 典型用途 | 代表 |
|---|---|---|---|
| **RLHF** | 先用人类的"哪个回答更好"偏好训一个**奖励模型**，再用它打分 | 对齐人类偏好（有用/无害/诚实） | ChatGPT |
| **RLVR** | 用**自动验证器**：答案对不对、代码过不过测试 | 提升数学/代码**推理**能力 | o1, DeepSeek-R1 |
| **DPO** | 直接用"好/坏"偏好对，绕开显式奖励模型，用类监督的损失逼近 RLHF 效果 | 轻量对齐 | 很多开源模型 |

> 本仓库的例子二用的是 **RLVR 思路**（答案对错可自动验证），算法是 **GRPO**。

### 3.4 优点
- **能突破示范的天花板**，发现更优甚至超越人类的解法。
- 直接优化你**真正在乎的目标**（有用、安全、做对率），而不是"像不像标准答案"。
- on-policy 训练修复 exposure bias，泛化通常更好（"SFT 偏记忆，RL 偏泛化"）。

### 3.5 局限
- **奖励难设计**：奖励没设好，模型会**钻空子（reward hacking）**——
  比如奖励"回答长"，它就废话连篇。
- **训练不稳定、贵**：要不停"生成→打分→更新"，算力消耗远大于 SFT。
- 可能**多样性塌缩**：为了拿高分，回答变得千篇一律。

## 4. 例子一：30 秒看懂差异（纯 Python，零依赖）

文件：`sft_vs_rl_demo.py` —— 运行：`python sft_vs_rl_demo.py`

**设定**：一个问题有 4 个候选回答 A/B/C/D。真实好坏：`D(1.0) > C(0.6) > B(0.3) > A(0.1)`。
但"人类老师"的示范里**几乎只示范稳妥的 C，很少给最优的 D**。

- **SFT** = 模仿老师的示范分布；
- **RL** = 自己采样回答、按真实奖励用策略梯度(REINFORCE)调整。

**真实运行结果：**

```
老师本人的平均水平 = 0.550

仅 SFT     策略分布[ A:0.05  B:0.15  C:0.75  D:0.05 ]  ->  平均回报 = 0.550   # 完美复制老师
仅 RL      策略分布[ A:0.00  B:0.00  C:0.00  D:1.00 ]  ->  平均回报 = 0.999   # 自己发现了最优 D
SFT->RL    策略分布[ A:0.00  B:0.00  C:0.00  D:1.00 ]  ->  平均回报 = 0.999   # 先模仿再超越
```

**结论**：
- SFT 学成了"老师的复制品"，水平被**死死锁在 0.55**——老师没教好的 D，它永远学不会。
- RL 通过**自己试错探索**，发现了老师很少示范的最优解 D，平均回报冲到 **0.999**。
- 这就是 RL 最迷人的地方：**能超越示范数据的天花板**（现实版：AlphaGo 的"第 37 手"、
  DeepSeek-R1 自己学会反思推理）。

## 5. 例子二：用真实 Qwen 模型跑 SFT 和 RL

模型：`Qwen/Qwen2.5-0.5B-Instruct`（0.5B，很小，Mac/CPU 也能跑），用 **LoRA** 轻量微调。

```bash
pip install -r requirements.txt
python qwen_sft.py        # A：监督微调（模仿示范的解题风格）
python qwen_rl_grpo.py    # B：强化学习（GRPO，按奖励提升做对率）
```
> 首次运行自动下载模型（约 1GB）。RL 比 SFT 慢很多，Mac 上可先把 `qwen_rl_grpo.py`
> 里的 `max_steps` 改小（如 30）感受趋势。脚本会自动选 GPU(cuda)/苹果GPU(mps)/CPU。

### 5.1 A — `qwen_sft.py`：SFT = 模仿（含真实运行结果）
- 我们造了一批**风格统一**的示范：`我们来计算 … 所以最终答案是 \boxed{…}`。
- SFT 后，模型回答会**模仿出这种风格**——哪怕是训练时没见过的新题。

**本机（Apple MPS）真实运行结果：**
```
训练【前】 问：计算 37 + 48
          答：37 + 48 = 85                          ← 原始风格：简短直给

训练【后】 问：计算 37 + 48
          答：我们来计算 (37 + 48) 这个简单的加法问题。(37 + 48 = 85)，所以最终答案是 \boxed{85}。
          问：计算 88 - 19   ← 训练时没出现过的新题
          答：我们来计算 (88 - 19) 这个简单的减法问题。(88 - 19 = 69)，所以最终答案是 \boxed{69}。
```
> 看到没？SFT **改变的是"行为/风格"**：模型把示范的口吻学了过去，还迁移到了新题上。
> 这就直观说明了"监督微调 = 模仿示范"。

### 5.2 B — `qwen_rl_grpo.py`：RL = 按奖励自我改进
- **不给标准答案**，只给一个打分器（奖励函数）：
  ```python
  答案数值正确         -> +1.0      # 这才是真正想优化的目标
  输出里含 \boxed{}     -> +0.2      # 先把格式带起来，答案才能被解析
  ```
- 模型对每道题**自己生成 8 个**答案，GRPO 比较它们的得分，强化高分的、抑制低分的。
- 训练前后各跑一遍评测，你会看到**做对率 / 格式合规率上升**。
- 这正是 **RLVR（可验证奖励强化学习）** 的迷你版——DeepSeek-R1 / o1 提升推理能力用的就是这套思想。

**本机（Apple MPS）真实运行结果（仅 60 步 GRPO，约 5 分钟）：**
```
RL 训练【前】  做对率 23%  | 含 \boxed 格式 37%
RL 训练【后】  做对率 40%  | 含 \boxed 格式 50%      ← 没给一条标准答案，全靠奖励涨上来

同一道题 92 + 92 的变化：
  训练前：92 + 92 = 184                                ← 算对了，但没用 \boxed{}，拿不到分
  训练后：92 + 92 = 184  所以最终的答案是 $\boxed{184}$。  ← 自己学会了"能拿高分"的格式
```
> 关键：训练数据里**从来没有标准解法**，模型纯靠"做对 / 格式"的奖励，自己摸索着把
> 做对率从 23% 提到 40%。步数越多、提升越大（这里只跑 60 步演示趋势）。
> 对比例子一：SFT 只会复制老师，RL 却能**自己找到老师没明说的更优行为**。

> **小实验**：故意把奖励改成"回答越长越好"，你会看到模型开始**废话连篇**——
> 这就是 **reward hacking（奖励钻空子）**，理解它对设计 RL 至关重要。

## 6. 关键概念小词典（小白必懂）

- **Policy（策略）**：就是模型本身——给定输入，它输出各种回答的概率分布。
- **Token / 自回归**：模型一个字一个字地预测下一个 token。SFT/RL 都作用在这个生成过程上。
- **交叉熵损失**：SFT 用它把"标准答案"的概率往上拉。
- **Reward（奖励）**：RL 里给一段输出打的分。可来自人（偏好）或程序（验证器）。
- **Reward Model（奖励模型）**：RLHF 中，用人类偏好数据训出来的"自动打分器"。
- **On-policy / Off-policy**：用**模型自己当前生成**的数据训练叫 on-policy（如 PPO/GRPO）；
  用别处来的数据叫 off-policy。on-policy 是 RL 修复 exposure bias 的关键。
- **Exposure bias（曝光偏差）**：SFT 训练只见过"正确前缀"，真实生成却要面对"自己的输出"，
  一步错容易步步错。
- **KL 惩罚**：RL 时限制新模型别偏离原模型太远，防止训崩/失去语言能力（`beta` 参数）。
- **PPO / GRPO / DPO**：
  - **PPO**：经典 RLHF 算法，需要额外的价值网络，重。
  - **GRPO**：DeepSeek 提出，**同一题多采样、组内比较**，去掉价值网络，更轻——本例所用。
  - **DPO**：不显式做 RL，用偏好对直接优化，像"加强版 SFT"，简单稳定。
- **RLHF / RLVR**：奖励来自**人类偏好** vs 来自**自动验证**（对错、测试通过）。
- **Reward Hacking（奖励钻空子）**：模型找到"骗高分但没真变好"的捷径。RL 头号大坑。
- **LoRA**：只训练插入的极少量参数，省内存/算力，效果接近全量微调（本例两脚本都用）。

## 7. 什么时候用哪个？

| 你的目标 | 选择 |
|---|---|
| 教模型一种**固定格式/风格/语气** | SFT |
| 让模型**听懂指令、学会一类任务的基本套路** | SFT |
| 有大量**高质量标准答案** | SFT（性价比最高）|
| 要对齐**人类偏好/价值观**（有用、无害） | RLHF / DPO |
| 要提升**数学/代码/逻辑推理**，且答案可自动验证 | RLVR（GRPO）|
| 想**超越现有示范**的天花板 | RL |
| 追求又快又稳又强 | **SFT 打底 → RL 拔高**（工业界标准流水线）|

## 8. 常见坑 & FAQ

- **Q：SFT 不是也能提高做对率吗，为什么还要 RL？**
  A：能，但 SFT 的上限被示范锁死，且它"背"的成分多、泛化弱。RL 直接优化"做对"这个目标，
  能探索出示范里没有的更优解（例子一的 0.55 → 0.999 就是铁证）。

- **Q：RL 一定比 SFT 好吗？**
  A：不。RL 贵、不稳、易被奖励钻空子。没有好的 SFT 底座，RL 很难练起来。
  二者**互补**，不是替代。

- **Q：DPO 算 RL 吗？**
  A：它实现上像监督学习（没有"采样→打分"的循环），但目标和 RLHF 一致（对齐偏好），
  常被归为"偏好优化"。可以理解成"用 SFT 的方式达到 RL 的目的"。

- **Q：Mac 上 RL 跑得很慢？**
  A：正常。RL 要反复生成，算力消耗大。把 `max_steps` 调小先看趋势，或用带 GPU 的环境。

- **Q：（实测踩坑）为什么 SFT 练着练着，模型开始输出乱码/复读？**
  A：这叫**过拟合塌缩**。小模型 + 高度重复的数据，如果把 loss 压得很低（如 0.1），
  模型会"死记"训练样本而**丧失正常生成能力**，自由生成时输出 `系统系统系统…` 这类乱码。
  本仓库实测：loss≈0.5~0.6 时模型刚好学会风格且连贯；继续硬练到 0.1 就崩了。
  **解法**：适中的学习率/轮数、`alpha=r`（缩放 1.0）、只对答案算 loss
  （prompt-completion 格式）、必要时早停。这正是"SFT 不是练越久越好"的真实写照。

## 10. 一句话收尾

> **SFT 教模型"模仿地说对话"，RL 教模型"自己想办法把事做好"。
> 先模仿打底，再试错拔高 —— 这就是今天每一个强大对话模型的成长之路。**
